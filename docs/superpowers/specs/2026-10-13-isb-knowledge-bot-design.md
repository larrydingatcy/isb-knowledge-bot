# ISB 双语知识库与问答机器人设计规格

**日期：** 2026-10-13  
**状态：** 待用户最终确认  
**目标仓库：** `larrydingatcy/isb-knowledge-bot`  
**公开入口：** `https://larrydingatcy.github.io/isb-knowledge-bot/`

## 1. 背景与目标

为 ISB 家庭建立一个无需登录即可访问、可分享的中英文知识库与问答机器人。系统定期收集 ISB 官网、Dragons’ Gate 及经管理员确认的其他官方来源，把分散的学校信息整理为带来源、带更新时间的结构化知识，并通过自然语言问答提供查询。

系统必须长期可维护和扩展：后续可以新增站点、上传支持文档、替换模型或搜索组件，并在不重写整套系统的情况下增加新功能。

## 2. 成功标准

- 用户可用中文或英文提问，系统使用相同语言回答；必要时可提供双语回答。
- 所有事实性回答至少附一个可核验的官方来源，并展示最后核验时间。
- 对无可靠依据、内容冲突或信息过期的情况明确说明，不猜测、不虚构。
- ISB 公开官网内容每天自动扫描；Dragons’ Gate 内容由已登录的本地 Mac 定期同步。
- 公开网页不要求登录，支持手机和桌面浏览器，并可通过链接直接分享。
- 管理员可新增数据源和上传文档，而无需修改问答核心逻辑。
- API 密钥、登录态、原始受限页面及个人信息不得进入公开仓库或前端。
- 抓取、清洗、脱敏、去重、检索、限流和部署均有自动化测试或可重复的验收步骤。

## 3. 范围

### 3.1 首期包含

- ISB 公开官网及经确认的相关官方网页。
- Dragons’ Gate 中与学校活动、日历、餐饮、交通、表格、政策和家长事务有关的内容。
- 中文和英文问答。
- 快捷分类：校历、课后活动、餐饮、课表、交通、表格与政策。
- 近期重要信息和内容变更摘要。
- 官方引用、发布时间、抓取时间、信息状态和置信提示。
- 管理员文档上传与新增来源机制。
- GitHub Pages 前端、Vercel 服务端 API、OpenAI 付费 API。

### 3.2 首期不包含

- 自动替用户向学校提交表格、付款、报名或发送消息。
- 将孩子姓名、班级、账户余额、个人课表等私人数据公开到知识库。
- 绕过 Dragons’ Gate 登录、验证码或访问控制。
- 面向公众开放的匿名知识库写入权限。
- 对学校政策或截止日期作无来源推断。

## 4. 用户与权限

### 4.1 访客

- 无需登录即可搜索、浏览分类和使用中英文问答。
- 只能读取已发布、已脱敏的知识。
- 不能修改来源、上传知识库文档或触发发布。

### 4.2 管理员

- 使用独立的受控入口管理来源、上传文档、预览变更和触发同步。
- 首期优先采用 GitHub 身份与仓库权限作为管理边界；本地同步工具复用用户已经登录的浏览器会话。
- 管理入口与公开站点分离，公开页面“不登录”的要求不受影响。

## 5. 总体架构

系统采用“公开静态前端 + 私有服务端问答 + 可插拔采集管道”的混合架构。

1. **GitHub Pages 前端**：承载公开聊天页面、分类浏览、最近更新、来源详情和状态提示。
2. **Vercel Serverless API**：执行检索、上下文组装、OpenAI 调用、输出校验、速率限制和用量控制；所有密钥只保存在服务端。
3. **GitHub Actions 公共采集器**：每天扫描公开官方页面，生成标准化知识条目并在校验通过后更新公开索引。
4. **本地 Dragons’ Gate 同步器**：在用户 Mac 上利用现有登录会话读取授权页面，先本地清洗和脱敏，再把允许公开的结构化条目提交到仓库。
5. **文档摄取器**：管理员上传 PDF、DOCX、TXT、Markdown 或 HTML；系统解析、分段、去重、标注来源和审核状态后进入同一知识管道。
6. **知识存储与索引**：首期使用仓库内版本化的结构化文件和轻量检索索引，保留未来迁移到托管向量数据库或全文搜索服务的接口。

## 6. 开放性与可扩展设计

### 6.1 来源适配器

每个来源通过统一适配器接口接入，而不是把抓取规则写死在主流程中。适配器至少返回：

- 来源 ID、标题、规范 URL 和来源类型；
- 原始发布日期与抓取时间；
- 正文、语言、可见性和内容哈希；
- 建议分类、有效期、附件和解析告警。

新增普通站点时，管理员优先只需在 `config/sources.yml` 增加配置；需要登录或特殊解析的网站可新增独立适配器模块。适配器必须遵守网站访问规则、权限和限速策略。

### 6.2 文档上传

- 提供管理员专用上传流程，公开访客不能把内容直接写入知识库。
- 上传后先进入 `draft` 状态，完成病毒/文件类型检查、文本提取、个人信息扫描、重复检测和预览。
- 管理员确认后才发布；每份文档保留文件名、来源说明、上传人、上传时间、版本、有效期和内容哈希。
- 受版权或访问限制的文档默认只保存必要的结构化摘要与引用信息，不公开原文件。

### 6.3 稳定模块边界

系统拆分为来源采集、内容解析、脱敏、知识规范化、索引、检索、模型调用、答案校验、界面和发布模块。模块之间使用版本化数据契约，避免某个模型、数据库或部署平台成为不可替换依赖。

### 6.4 升级能力

- AI 模型通过服务端 provider 接口调用，未来可切换模型或增加备用模型。
- 检索器通过统一接口支持关键词、混合检索和向量检索的渐进升级。
- 知识条目包含 `schema_version`，升级时使用可回滚的数据迁移脚本。
- 新功能通过独立页面或功能开关上线，例如通知订阅、管理分析、更多语言或家庭私有空间。
- API 使用版本前缀，避免前端升级与后端升级强耦合。

## 7. 数据模型

每个知识条目至少包含：

- `id`：稳定唯一标识；
- `schema_version`：数据结构版本；
- `title`、`content`、`language`；
- `category`、`tags`；
- `source_id`、`source_url`、`source_type`；
- `published_at`、`valid_from`、`valid_until`、`crawled_at`；
- `content_hash` 和上游版本；
- `visibility`：公开、仅管理员或禁止发布；
- `review_status`：草稿、已审核、自动发布、已过期、已撤回；
- `confidence` 与解析告警；
- 可选的英文/中文对应条目关系。

公开索引只包含 `visibility=public` 且通过校验的条目。原始 Dragons’ Gate HTML、Cookie、会话数据和被脱敏内容只存在于本地临时目录，并在同步完成后按保留策略清理。

## 8. 采集与更新流程

### 8.1 公开官网

1. GitHub Actions 每天运行一次，也支持管理员手动触发。
2. 读取 `sources.yml`，按来源限速抓取。
3. 提取正文和元数据，计算内容哈希。
4. 仅对变化内容执行清洗、分类、去重和索引更新。
5. 运行质量校验；失败时保留上一版可用数据并记录告警。
6. 提交机器可读的变更摘要并发布静态站点。

### 8.2 Dragons’ Gate

1. 本地计划任务默认每周运行，并支持手动“立即同步”。
2. 只使用用户合法的现有登录会话，不存储或上传登录凭据。
3. 页面内容在本地提取、脱敏和分类。
4. 对涉及儿童、家庭、账号或个别人员的信息默认阻止发布，需管理员显式确认才可继续。
5. 仅将批准的结构化知识条目和必要引用元数据提交到公开仓库。
6. 若发现重要日期变化，可立即触发公开索引更新。

### 8.3 文档上传

1. 管理员选择文件并补充来源、分类、有效期和公开权限。
2. 服务或本地工具执行安全检查、解析、分段、去重和个人信息检测。
3. 管理员预览将公开的文本和引用。
4. 确认后生成知识条目并更新索引；撤回文档时对应条目也被撤回。

## 9. 问答流程

1. 前端把问题、界面语言和可选分类发送到 `/api/v1/chat`。
2. API 验证长度、速率和请求来源，不接受任意系统提示或外部工具指令。
3. 检索层只从已发布知识中寻找相关片段，并按来源权威性、时效和相关性排序。
4. 服务端将最少必要片段发送给 OpenAI 付费 API。
5. 模型被要求只基于给定资料回答，区分事实、缺失信息和冲突信息。
6. 答案校验器确认引用存在、链接属于允许来源、日期和断言有依据。
7. 前端展示答案、引用、更新时间、信息状态和必要的“请向学校确认”提示。

任何资料不足的问题都返回明确的“不知道/未找到可靠资料”，并给出建议查阅的官方入口，而不是生成猜测答案。

## 10. 产品界面

### 10.1 首页

- 中英文切换；默认跟随浏览器语言。
- 对话输入框和建议问题。
- 校历、课后活动、餐饮、课表、交通、表格、政策快捷入口。
- “近期重要信息”与“最近更新”。
- 明显展示资料更新时间与服务状态。

### 10.2 答案卡片

- 简洁答案；可展开查看细节。
- 每项关键事实对应官方引用。
- 显示来源标题、来源站点、发布日期/抓取时间、是否可能过期。
- 支持复制和分享问题链接，不把聊天中的敏感文本编码进公开 URL。

### 10.3 管理工具

- 来源列表、最近同步状态和失败原因。
- 新增/停用来源、手动刷新。
- 文档上传、解析预览、脱敏预览、发布/撤回。
- 内容变更对比与审核记录。

管理工具可以先以本地命令行和 GitHub 工作流形式交付，接口保持稳定，之后升级为受保护的网页控制台。

## 11. 安全、隐私与合规

- OpenAI、Vercel 和其他服务密钥只保存在 Vercel Environment Variables 或 GitHub Secrets。
- 浏览器前端永远不包含服务端密钥。
- 原始 Dragons’ Gate 页面、SSO 数据、Cookie 和浏览器配置不得提交到 GitHub。
- 默认脱敏姓名、学生 ID、邮箱、电话、住址、班级个人安排、费用余额和账户信息。
- 抓取页面和上传文档一律视为不可信数据，禁止其内容改变系统指令、调用工具或访问密钥，以抵御提示注入。
- 公开 API 设置每 IP 速率限制、问题长度限制、并发限制和月度预算上限；达到上限时提供友好降级提示。
- 记录最少必要的匿名运行指标，不保存完整私人提问；日志设定短期保留和删除策略。
- 若机器人滥用显著，再启用无感挑战或更严格的防护，但不把普通用户登录作为首期要求。
- 所有公开信息遵循来源的使用条款与合理引用原则；有疑问的内容进入人工审核，不自动发布。

## 12. 可靠性与异常处理

- 某来源抓取失败时继续提供上一版知识，但标记可能过期并显示最后成功时间。
- 页面结构变化导致解析异常时停止该来源的新版本发布，避免用空数据覆盖有效数据。
- 同一事实来源冲突时同时展示差异，优先最新且更权威来源，并建议向学校确认。
- OpenAI 或 Vercel 暂时不可用时，静态知识浏览仍可工作；聊天界面显示服务暂不可用。
- 发布流程支持回滚到上一版索引。
- 同步失败、预算临界和持续解析错误产生管理员告警；正常且无变化时保持安静。

## 13. 测试与验收

### 13.1 自动化测试

- 来源适配器契约测试与固定样本解析测试。
- 个人信息脱敏测试和禁止发布规则测试。
- 内容哈希、去重、更新、撤回和数据迁移测试。
- 中英文检索和引用映射测试。
- 提示注入、越权来源、恶意上传和无引用回答拦截测试。
- API 速率限制、预算保护、超时和降级测试。
- 前端关键路径、响应式布局和无障碍基础检查。

### 13.2 上线验收

- 中文和英文各完成一组真实问题验证。
- 每个事实性答案至少有一个可点击的官方引用。
- 对未知信息明确拒绝猜测。
- 新增一个测试站点无需修改问答核心代码。
- 上传一份测试 PDF，经过预览、审核、发布和撤回完整流程。
- Dragons’ Gate 样本确认无个人信息或登录态进入 Git 历史。
- GitHub Actions、Vercel API、GitHub Pages 和本地同步各完成一次端到端验证。
- 手机和桌面浏览器均可使用，公开访问无需登录。

## 15. 实施原则与阶段

### 阶段一：可用基础版

建立数据契约、公共站点采集、基础知识索引、双语聊天、引用展示、GitHub Pages 与 Vercel API。

### 阶段二：受限来源与管理能力

加入 Dragons’ Gate 本地同步、严格脱敏、上传文档、审核/撤回和变更摘要。

### 阶段三：增强与开放升级

按使用情况增加混合/向量检索、受保护网页管理台、通知订阅、更多语言、可观测性和其他来源适配器。

每个阶段都必须保持公开站点可用、数据格式可迁移、旧索引可回滚。任何扩展不得削弱首期的隐私边界和引用要求。

## 16. 已确认的产品决策

- 建立独立仓库，而不是修改现有 `dayx-timetable`。
- 公开页面无需登录，可自由分享。
- 使用 OpenAI 付费 API，由服务端调用。
- ISB 公开官网每日云端扫描。
- Dragons’ Gate 通过用户 Mac 的已登录浏览器定期同步，默认每周并支持手动刷新。
- 允许经脱敏和审核的 Dragons’ Gate 学校信息进入公开知识库。
- 采用 GitHub Pages 前端加 Vercel Serverless API 的混合部署。
- 系统必须可新增站点、支持管理员上传文档，并保留后续功能升级能力。

## 17. 待实施计划细化的非产品性选择

以下选择不改变已确认的用户体验和安全边界，可在实施计划中依据当前生态、成本和可测试性确定：

- 前端框架与构建工具；
- 首期全文检索库和索引文件格式；
- Vercel 上的限流存储实现；
- 本地计划任务使用 macOS `launchd` 还是现有 Codex 自动化；
- 管理文档上传首期采用本地工具、GitHub 工作流还是受保护的轻量管理页。
